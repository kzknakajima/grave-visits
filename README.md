# お墓参り記録(家族共有)

GitHub Pages で公開する、家族で読み書きできるお墓参り記録アプリです。
バックエンドに Firebase (Firestore) を使っています。

## 公開後にやること(初回のみ・あなたの作業)

Firebase プロジェクトの作成だけは Google アカウントでの操作が必要なため、
以下の手順を実施してください。

1. https://console.firebase.google.com/ を開き、Google アカウント(このアプリで使っているものでOK)でログイン。
2. 「プロジェクトを追加」→ 適当な名前(例: `grave-visits`)で作成。Google アナリティクスは無効のままでOK。
3. 左メニューの「Firestore Database」→「データベースの作成」。
   - ロケーションは `asia-northeast1` (東京) がおすすめ。
   - モードは「本番環境モード」でOK(ルールはこの後上書きします)。
4. 作成後、「ルール」タブを開き、このリポジトリの `firestore.rules` の中身を
   そのまま貼り付けて「公開」をクリック。
5. 左上の歯車アイコン →「プロジェクトの設定」→ 下の方の「マイアプリ」→
   `</>`(ウェブ)のアイコンをクリックしてウェブアプリを登録(アプリ名は何でも良い、
   Firebase Hosting は不要)。
6. 表示された `firebaseConfig` オブジェクトの中身をコピーし、
   このリポジトリの `firebase-config.js` の該当箇所に貼り付けて保存・コミット。
7. GitHub Pages の URL(例: `https://kzknakajima.github.io/grave-visits/`)を開いて、
   記録の追加・編集ができることを確認。

## セキュリティについて

- `firebase-config.js` の中身(apiKey 等)はクライアント側で公開される前提の値なので、
  リポジトリにそのままコミットして問題ありません。
- 実際のアクセス制御は Firestore の「セキュリティルール」(`firestore.rules`)で行っています。
  現在の設定は「ログイン不要で誰でも読み書きできる」内容です。
  ページの URL を知っている人だけがアクセスする、という前提で運用してください
  (URL を SNS 等で公開したり、検索エンジンにインデックスされる場所にリンクしたりしないでください)。
- より厳密に守りたくなった場合は、Firebase Authentication で家族用の合言葉/招待制ログインを
  追加することもできます(必要になったら相談してください)。

## ローカルでの見た目確認

このディレクトリを任意のHTTPサーバーで配信すれば動作します。例:

```bash
npx serve .
```

(`file://` で直接開くと ES Modules の関係でブラウザによっては動かないことがあります)
